# BEYOND PHYSICS — 프로젝트 개발 지침 v1.5

갱신:2026-11-05 KST. 사용자 최초 지침 v1.0과 이후 확정한 변경사항의 작업 기준이다.

## 출품 프로토타입 마무리 방향

사용자 결정에 따라 당분간 새 맵을 추가하지 않는다. 기존 직선 얼음·곡선 얼음·안개 고속도로 세 맵의 디테일과 사용 경험을 완성하고, 접수양식(기획서)·시연 영상·GitHub 소스/APK·제출 준비로 진행한다. 당장의 우선 작업은 세 맵별 조명·공조·사운드와 복원/선택 UI 완성이다. 공식 기술 활용성은 경험에 적절한 SDK 사용이며 기능 개수별 가산점이라고 주장하지 않는다.

조명·공조는 각각 초기OFF인 선택 기능, 소리는 초기ON/음소거 가능이다. 물리상태→효과 정책→Unreal 오디오/SDK 출력으로 분리하고 물리에 개입하지 않는다. 실제 capability/영역/권한/원본값을 확인한 기능만 변경하며 실제getter로 적용을 확인한다. 사용자 변경은 양보하고 앱 소유 값만 복원한다. 출력 요청은 직렬화·중복 제거·1.5초 heartbeat 제한을 적용한다. 강제 종료·서비스 단절 후 즉시 복원을 보장하지 않고 남은 복원 기록을 다음 연결 때 재시도한다. 실제 실차 활성화는 별도 승인 전 허용하지 않는다.

맵별 색/팬/냉감/소리는 감각 연출이다. 소리는 자체 합성 가상 전동차 음향이며 Pleos TTS라고 표시하지 않는다. 공조는 기존 전원ON/AUTO OFF인 지원 영역만 사용하고 전원·자동모드·제상·송풍 방향을 임의로 바꾸지 않는다. 앱 내부 소리만 제어하며 전체 차량 음량을 올리지 않는다. 실제 오디오 포커스의 초기 허용과 손실을 따로 처리한다. 상세 정책·수정 위치는 docs/MAP_FEEDBACK.ko.md를 따른다.

## 목표

Pleos Connect 기반의 정차 중 물리 체험 앱을 만든다. 자체 C++ 차량 모델의 설명 가능성과 차량 인터페이스 결합이 핵심이다. Unreal은 실제처럼 보이는3D 차량·환경 표현에 사용한다. 중앙 인포테인먼트와 클러스터가 장기 표시 목표이며, 실제 클러스터 지원은 별도 확인한다.

## 확정된 입력 설계 — 자동 가속·브레이크 중심

- 사용자의 가속페달 입력은 수집하거나 사용하지 않는다.
- 얼음 맵 시작과 R 재시작은 속도0에서 시작하고, 첫 물리 틱부터 가상 구동력을 자동 요청한다. 사용자 피드백으로 안개 맵03만 초기조건80km/h로 시작한다. 이후 운동은 물리 적분으로 계산한다.
- 브레이크 입력이 있으면 자동 구동 요청을0으로 만들고 제동력을 요청한다. 기본 직선 얼음 맵에서는 브레이크를 놓으면 자동 가속한다.
- 두 번째 곡선 맵만 완만한 구동 요청(throttle 최대0.12)과 제동 후 낮춘 가속 목표 유지를 적용한다. 초기 목표50km/h·출발 하한15km/h는 게임 정책이며 실도로 안전속도가 아니다. 목표 초과 시 구동만 끊고 내리막 가속은 그대로 계산한다. 첫 맵 입력 정책과 μ0.12는 유지한다. 진입 속도·현재/직전 궤적·μ·결과를 비교하며 실험/리플레이를 일반 완료 기록에 섞지 않는다.
- 세 번째 안개 맵은 건조 아스팔트 대표 μ0.8·4km 직선·3차로·초기80/목표100km/h다. 안개 진입까지 약30m, 첫 차량 범퍼까지255.04m다. 차로별 정차 차량 한 대씩 중앙x0/좌x45/우x85m에 처음부터 존재하고 안개 때문에 접근하며 드러난다. 움직인 뒤 제동하면 자동 구동을 해제하고 RESTART 전에는 다시 가속하지 않는다. 선언된30m 기준과 실제 사람의 발견 시각을 구분한다. 예방 제동은 기준 이전에도 정상 정지 결과로 기록하고 반응시간은N/A다. 기준 차량과 접촉 차량의 번호를 별도로 저장한다.
- PC는 S 제동, A/D 조향이며 W는 사용하지 않는다. Space 일시정지와 벽 접촉 종료 상태에서는 자동 가속도 중단된다.
- 가속은 위치·속도 강제 변경이나 시간배속이 아닌 기존 타이어 접지력·차량 질량·수치적분으로 계산한다. 두 번째 맵의 목표 기반 구동 요청은 별도 입력 정책으로 설명한다. 속도 강제 고정·자동 제동·공력 기반 최고속도 모델은 추가하지 않는다.
- B/T 실험과 기록 입력 재생, 개발용 원시 입력 주입은 기본 자동 가속 정책과 분리한다.
- Pleos 단계는 공식 실행 제한과 지원되는 브레이크·조향 상태를 연결한다. 현재 확인한 브레이크 신호는 눌림 여부이며 페달 압력이나 연속 제동량으로 표시하지 않는다.
- 실제 가속페달을 사용하지 않는 결정이 실제 브레이크·조향을 무해하게 만들지는 않는다. 제조사 승인 전 실차 핸들·페달 게임 테스트를 하지 않는다.

## 물리 원칙

안개 맵03만 일반 승용차 가정의18:1 조향비·이상 Ackermann 기하·네 접지점별 힘/요모멘트 계산을 적용한다. 휠베이스2.7m/윤거1.88m/질량1500kg/Iz2500kg·m²다. 현재 접지점 속도로 슬립을 계산하며 조향각으로 경로나 요각을 직접 지정하지 않는다. 키보드 가상 핸들 보간과 실제 SDK 입력 처리를 구분한다. 기존 모델과 영윤거 극한·해석적 제동·저속/고속 정상선회·에너지·대칭성을 비교한다. 실측 특정 차량·ABS·휠 각운동·동적 하중이동까지 검증한 모델이라고 주장하지 않는다. 상세 가정과 출처는 docs/FOG_FEEDBACK_PHYSICS.ko.md에 기록한다.

물리 정확성을 시각 효과보다 우선하고, 게임적 입력 정책과 물리 모델을 구분한다. 모델마다 목적·방정식·가정·유효 범위·단위·출처·적분법·기준 결과·오차·한계를 기록한다. 복잡한 모델은 기본 모델과 비교 후 도입한다. 생성형 AI로 실시간 운동을 결정하지 않는다. 개발자가 계산 원리를 설명할 수 있어야 한다.

현 구현은 가상 AWD, 마찰원 한도와 Fiala 형태 횡력, 고정1/240초 적분이다. μ는 일반0.85/저마찰0.12이다. 직선 맵은 평면3자유도이며 가상 램프는 작은 경사에서 중력 투영·준정적 수직하중을 추가한 축소 모델이다. 롤/피치 관성·서스펜션·동적 하중이동은 계산하지 않는다. 질감·조명은μ와 다른 표현이다. 충돌 시 종료는 게임 규칙이며 충격량·반발·파손 모델이 아니다.

## 그래픽 원칙

실사에 가까운 지형·PBR 재질·조명·분위기를 목표로 한다. 원경 능선과 근경 재질의 반복·늘어짐, 노출·명암, 운전 시 도로 식별성을 실제 실행 화면으로 확인한다. 양질의 외부 자산은 출처·라이선스를 기록한다. 도로에는 얼음 질감을 사용하지 않는다. PC 시연 품질과 차량 APK의 자원 예산을 분리하여 확인하고, PC에서 보기 좋다는 이유로 차량 성능 검증을 대신하지 않는다.

## 안전과 차량 연동

공식 주차·주행 제한 정책에서 허용될 때만 실행한다. 주행 전환 시 즉시 중단·UI 숨김·재개 차단을 적용한다. 차량 구동계 분리나 가속/RPM 차단 기능이 공개 SDK에 있다고 가정하지 않는다. 실제 액추에이터를 우회 제어하지 않는다. 공조·조명·시트는 지원·권한과 사용자 선택을 확인하고, 과도한 작동을 피하며 종료·오류 시 원래 설정 복원을 시도한다.

## 개발 순서와 검증

선행 연구·API 확인 → 최소 차량/환경 → 기본 운동 검증 → 저마찰 비교 → 차량 입력·실행 제한 연결 → 사운드/조명 → 저중력과 확장 환경 순서를 유지한다. 사용자의 후속 지시에 따라 예외 시험을 계속 늘리며 실제 구현을 지연하지 않는다. 새 동작에 필요한 검사와 미검증 항목의 명시는 유지한다.

문제 정의 → 물리 모델 → 최소 구현 → 실험 → 검증 → 개선 순서로 작업한다. 무마찰 운동·일정 감속·원운동과 향후 저중력 포물운동은 분석해와 비교한다. 시각적 유사성을 물리 정확성의 증거로 삼지 않는다.
