# 두 번째 맵: 속도 관리와 시도 비교

2026-11-03. 사용자 승인 범위는 두 번째 곡선 맵만이다. 첫 번째 직선 맵, μ0.12, 도로 형상과 타이어 힘 계산은 유지한다.

## 조작

곡선 맵은 정지 출발 후 완만하게 자동 가속한다. PC A/D 조향·S 제동, Pleos에서는 기존 SDK 조향·브레이크다. 브레이크는 항상 구동력을 끊는다. 브레이크를 놓으면 감속한 속도를 가속 목표로 유지하며 완만하게 구동한다. 정지 후 다시 출발할 수 있도록 목표의 하한은15km/h다. R/화면 RESTART는 초기 가속 목표50km/h로 새 시도를 시작한다.

50/15km/h는 게임 입력 정책의 설정값이며 실제 얼음길 권장 속도가 아니다. 내리막에서는 구동력을 끊어도 중력으로 속도가 증가한다. 자동 제동·속도 고정·경로 보정·자동 조향은 없다.

## 입력 정책과 물리의 구분

`Driving/RampAutoDrive.h`는 물리 힘이 아니라 가속·제동 입력을 만든다. 브레이크 해제 시 `throttle=clamp(0.25*(target-speed),0,0.12)`, 제동 시 throttle0이다. 제동 중 목표는 `min(기존 목표,max(15/3.6,현재 속도))`로 낮춘다. 초기 목표는50/3.6m/s다. 현재 DriveForce6000N에서 최대 가상 구동 요청은720N이며 실제 힘은 기존 타이어 모델과 마찰 한도가 계산한다.

직선 맵은 기존 AutoDriveInput을 그대로 호출해 브레이크 해제 시 throttle1을 요청한다. 공유 VehicleModel.cpp·μ·브레이크 힘·도로 자산은 바꾸지 않았다. 정지마찰·차륜 잠김/ABS·실차 타이어 보정의 기존 한계는 남아 있다.

## 비교 화면

오른쪽 패널에서 이번 시도(청록)와 직전 시도(주황)의 경로를 비교한다. BEND ENTRY는 중심선 station160m를 처음 앞으로 통과할 때의 속도로 고정 시간 샘플 사이를 보간한다. 아직 진입하지 않았으면 `--`다. 벽 접촉/종점에서 결과 패널에 진입 속도와 최대 중심선 이탈을 표시한다. 충돌 원인을 자동으로 속도 탓으로 단정하지 않는다.

각 시도의 μ도 표시·저장한다. PC의1/2 키로 일반/저마찰을 바꿔 비교할 때 서로 다른 노면 결과를 같은 조건으로 오해하지 않도록 한다.

재시작하면 직전 시도를 보존한다. 맵 전환/앱 재실행은 화면 비교 이력을 지울 수 있다. 리플레이·B/T/외부 시험 입력은 일반 시도로 완료 처리하지 않고 새 학습 시도에는 R이 필요하다.

종료·재시작 시 `Saved/RampTrials/ramp_*.csv`에 약1m 간격의 위치·속도 요약을 저장한다(최대4096점). 정확한 고정 시간 입력 재생 CSV인 기존 수동 E RECORD와는 목적이 다르다. Android 파일 위치는 앱의 Unreal Saved 경로이며 `BP_RAMP_RESULT` 로그에 실제 경로와 저장 성공 여부가 남는다.

## 비교 계산

`Tests/run-ramp-learning-scenarios.cmd`는 같은 조향 시험 운전자와 같은 초기 정지 상태로 두 시도를 비교한다. 감속 없는 시도는 진입46.4653km/h에서 station394.455m 부근 벽에 닿았고, 미리 제동한 시도는 진입21.5964km/h에서 station630.667m 종점까지 통과했다. 느린 시도의 최대 이탈은0.0881m였다. 위치·방향을 강제로 맞추지 않고 기존 타이어 힘으로 적분했다. 이는 특정 가상 모델/시험 조작 조건의 결과이며 모든 사용자의 성공이나 실도로 안전속도를 보장하지 않는다. 로그와 궤적은 docs/research/ramp-learning-scenarios.log 및 ramp-learning-fast/slow.csv에 있다.
