# 안개 맵 2차 수정 — 조향·차량 물리와 짧은 시나리오

2026-11-04 KST. 사용자 피드백1~5 및 ‘특정 차종 없이 근거를 기록한 일반 승용차’ 선택에 따른 변경이다. 새 모델은 우선 안개 맵03에서 사용한다. 두 얼음 맵은 기존 단일 궤적 모델을 유지해 비교 기준으로 남긴다.

## 플레이 변경

가상 차량은80km/h로 시작하고100km/h를 향해 자동 구동한다. 첫80은 초기조건이며 이후 속도나 경로를 강제로 보정하지 않는다. 시작점x=-260m, 안개 구역 시작x≈-230m로 약30m 후 진입한다. 첫 차량 범퍼까지 약255m, 미제동 접촉까지 약9.47초다. 종전1.9km 접근을 줄였다.

중앙(0,0), 왼쪽(45,+3.5), 오른쪽(85,-3.5)m에 정차 차량을 한 대씩 둔다. 물리 y는 왼쪽+, Unreal y는 오른쪽+이므로 렌더 좌표는 부호를 바꾼다. 진행방향 간격은45m·40m다. 차량은 처음부터 존재하며 갑자기 생성하지 않는다. 모든 차량에 같은 OBB 접촉/스윕을 적용한다.

안개는 반경450m/중심x220m/radial0.27/height mask1000이다. 결과의 선언된 기준을100m에서30m로 줄였다. 실제 발견거리는 대상 대비·화면·조명에 따라 달라진다. 시정30m를 실차 광학 장비로 보정했다는 뜻은 아니다.

μ0.8,100km/h의 이상 제동거리만49.16m이므로30m에서 차량을 발견한 뒤에는 즉시 전제동해도 공간이 부족하다. 30m는100km/h에서약1.08초 거리다. 이 어려움은 안개/배치와 계산된 접지력에서 나오며, 게임이 충돌을 강제하거나 조향/마찰을 임의로 약화시키지 않는다. 안개에 들어가기 전에 감속·정지하는 선택은 유효한 예방 제동 결과로 표시하고, 아직 기준을 통과하지 않았으면 반응시간은N/A다.

## 조향과 운동 계산

기존 단일 궤적 모델은 앞 차축 두 바퀴를 하나로 묶고 같은 조향각을 썼다. 새 안개 프로필은 네 접지점의 힘과 모멘트를 따로 계산하는 평면 강체 모델이다. 물리 적분은 기존240Hz 외부 고정 틱과0.5ms 이하RK4를 유지한다.

핸들각 θ(도), 가정 조향비 i=18에 대해 중앙 등가 조향각은 δ=clamp(θπ/(180i),±π/6)다. SDK의 rawSteering을 핸들각으로 사용한다. 예: 핸들90°→중앙 등가5°. 키보드 A/D는 가상 핸들을 최대540°/s로 움직이는 컨트롤러이며, 실제 차량 액추에이터나 사람 조작 속도를 계측한 값이 아니다. SDK 입력에는 이 키보드 보간을 적용하지 않는다.

휠베이스 L=2.7m, 윤거 t=1.88m에서 이상 Ackermann 조향은 다음과 같다.

```
δFL=atan2(L*sinδ, L*cosδ - (t/2)*sinδ)
δFR=atan2(L*sinδ, L*cosδ + (t/2)*sinδ)
```

곡선 안쪽 바퀴가 더 많이 꺾인다. 이는 기하학적 조향 가정이며 실제 고속 타이어가 미끄럼 없이 이 원을 따라간다고 강제하는 식이 아니다. 실제 운동은 현재 차량 속도와 각 바퀴 접지력으로 결정한다.

접지점 위치(xᵢ,yᵢ), 차체 속도(u,v), 요레이트 r에 대해 접지점 속도는 `(u-r*yᵢ, v+r*xᵢ)`다. 이를 각 바퀴 조향축으로 회전시켜 종·횡속도를 구하고 기존 Fiala형 횡력과 종력 요청/마찰원 포화를 바퀴별로 계산한다. 차축 강성과 하중·구동·제동 요청을 두 바퀴로 나눈다. 각 바퀴의 힘을 차체 좌표로 돌려 합산하며 요 모멘트는 `Σ(xᵢ*Fyᵢ-yᵢ*Fxᵢ)`다. `u_dot=Fx/m+r*v`, `v_dot=Fy/m-r*u`, `r_dot=Mz/Iz`를 적분한다. 월드 위치/진행 방향은 이 상태에서 계산하며 핸들각으로 직접 요각이나 궤적을 지정하지 않는다.

물리 계산에 쓴 바로 그 바퀴별 조향각을 렌더 회전과 바퀴 구름 속도 계산에도 사용한다. 물리 전륜x1.2m/후륜x-1.5m와 렌더 메시의 휠 아치를 맞추기 위해 차체 x스케일2.7/2.9, 중심오프셋-0.15m를 적용했다. 타이어의 시각적 구름 회전은 여전히 접지점 속도의 순수 굴림 근사다.

근거: [NVIDIA PhysX 차량 가이드](https://nvidia-omniverse.github.io/PhysX/physx/5.6.1/docs/Vehicles.html)의 바퀴별 힘/강체 합산과 Ackermann 설명, [공식 Ackermann 스키마](https://docs.omniverse.nvidia.com/kit/docs/omni_usd_schema_physics/latest/physxschema/class_physx_schema_physx_vehicle_ackermann_steering_a_p_i.html)의 좌우 비대칭·윤거·휠베이스 정의를 참고했다. PhysX 엔진으로 교체한 것은 아니며 자체 C++ 수식 구현이다.

| 값 | 현재 프로필 | 근거/상태 |
|---|---:|---|

특정 양산차와 동일하게 보정한 모델은 아니다. 서스펜션/롤/피치, 동적 하중 이동, 타이어 이완 길이, 휠 각속도·종슬립, ABS/ESC, 조향 컴플라이언스, 공력·구름저항은 없다. 단순 모델을 넘어섰다는 사실만으로 실차 정밀도를 보증하지 않는다. 이 확장의 검증 범위는 아래 로그와 비교식이다.

## 검증과 수정 위치

`ContactPatchChecks.cpp`에서 Ackermann cot 관계, 원운동 접지점 무슬립 기하, 바퀴별 마찰원, 힘/모멘트 합, 좌우/월드 회전 불변성, 윤거0에서 단일 궤적으로 환원, 전·후진 제동 에너지 감소, 제동 분석식을 확인했다. 작은 조향각에서 독립 선형 정상선회식과 비교한 요레이트는5m/s에서0.00900785(기준0.00900826),25m/s에서0.0269557(기준0.0272879)rad/s다. 속도 유지용 시험 조건을 게임에는 사용하지 않는다.

세 차량의 충돌과 가장 이른 스윕 접촉, 첫 기준 차량ID 유지, 다른 차량 충돌ID, 예방 정지를 별도 검사했다. 같은 코어의 짧은 접근 시험은 미제동9.47초 접촉, 기준 후0.5초 전제동 접촉, 기준 후0.5초 최대 랙 조향도 접촉, 미리 제동하면 정지였다. 이는 선언한 조건에서의 자동 입력 결과이며 모든 운전자/회피 경로가 실패한다는 증명은 아니다.

- `Physics/SteeringGeometry.h`: 핸들→조향비→Ackermann.
- `Physics/VehicleModel.cpp`, `VehicleTypes.h`: 바퀴별 접지점 속도·힘·모멘트와 파라미터.
- `Physics/FogHighway.h`: 초기80·목표100·세 차량 위치·30m 기준·접촉 스윕.
- `Experiment/FogTrial.h`: 최초 기준 차량 고정, 실제 충돌 차량ID, 예방 정지·반응/제동 거리.
- `Driving/DrivingPawn.cpp`: SDK/키보드 핸들 변환, 물리→화면 공통 바퀴각,80km/h 재시작.
- `Environment/FogHighwayScene.h/.cpp`, `Scripts/revise_fog_feedback.py`: 안개/세 차량 렌더 배치.

이 경로들은 모두 `unreal/BeyondPhysics/Source/BeyondPhysics` 아래이며 Scripts만 프로젝트 Scripts 폴더다. 결과 summary는 기준 차량/충돌 차량ID, 조향비, 최초 제동 시각/속도를 추가로 저장한다. 최초 기준의 간격은 이후 다른 차량을 치더라도 그 기준에 고정해 trace/HUD/summary가 같게 유지한다.
