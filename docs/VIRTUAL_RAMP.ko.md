# 두 번째 맵: 저마찰 가상 진출 램프

2026-10-30. 사용자가 원본 도면 복제 대신 공식 설계 기준을 참고한 가상 램프를 허용했다. 실제 특정 IC/JC의 도면이나 현황을 재현한 맵이 아니다.

2026-11-03 갱신: 두 번째 맵에만 완만한 자동 구동·제동 후 낮춘 가속 목표 유지·직전 시도 진입 속도/궤적 비교를 적용했다. 첫 맵 입력·μ0.12·공유 물리 모델과 두 도로 자산은 유지했다. 현재 조작과 수정 위치는 [속도 관리·비교 안내](RAMP_LEARNING.ko.md)를 참조한다. 아래 전구간 SDK 시험 제어기 실패는 이전 전체가속 정책의 기록이며, 새 정책의 계산 비교와 실제 APK 입력 검증은 별도 최신 실험 기록에 남긴다.

## 설계 근거와 선택값

기준 자료는 [도로의 구조·시설 기준에 관한 규칙](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lspttninfSeq=110543)의 평면곡선·편경사·완화구간·종단선형·연결로 항목이다(2026-06-03 시행본 확인). 기준의 허용 범위를 참고해 아래 가상 선형을 선택했다. 표준 최소값이 모든 램프의 실제 치수라는 뜻은 아니다. 설계속도50km/h는 형상 선택의 참고값이며 빙판에서의 안전속도·게임 속도 제한이 아니다. 전체 도로공학적 적합성, 대형차 궤적·시거·접속부 용량은 인증하지 않았다.

| 요소 | 구현값 |
|---|---|
| 곡선 | 우회전90°, 원곡선 반경150m |
| 완화곡선 | 앞뒤 각60m, 선형으로 변하는 곡률의 클로소이드 |
| 직선 접근/출구 | 160m /180m |
| 전체 중심선 길이 | 635.619449m |
| 차로 | 기존과 같은3차로, 차로당3.5m |
| 길어깨/전체 포장폭 | 좌우 각1.5m /13.5m |
| 최대 편경사 | 4%, 우회전 안쪽이 낮음; 완화곡선에서 접속 |
| 종단 경사 | -3%; 진입·복귀 포물선 전이 각60m |
| 높이 | 시작20m, 끝 약9.33m; 기존 배경과 겹치지 않기 위한 장면 배치 기준 |
| 마찰계수 | 0.12, 기존과 동일한 가상 저마찰 프로파일 |

완화구간의 곡률은 `k(s)=-s/(R*L)`이고, 진입 방위각은 `psi(s)=-s²/(2RL)`이다. 중심선은 이 방향의 cos/sin을 적분한다. 렌더링 메시와 물리 경계는 같은 C++ 노드에서 나온 좌표를 사용한다. 도로 외형은 아스팔트이며 얼음 텍스처를 추가하지 않았다. 기존 산·재질·가로등 외형을 재사용했다. 새 가로등은 발광 재질을 쓰며 다수의 추가 동적 조명은 만들지 않았다.

## 실행

최종 APK 하나에 두 맵을 함께 넣는다. 기본 시작은 기존 직선도로다.

2026-10-30 설치·실행 검증 완료. 현재 에뮬레이터는 곡선 시작점에서 재시작을 기다리므로 **RESTART / TAP**을 누르면 자동 가속한다. 검증 범위와 실패·한계는 [실험 기록](research/2026-10-30-virtual-ramp-results.ko.md)에 함께 기록했다.

- 상단 **MAP 02: CURVE / TAP**: 곡선 맵으로 전환.
- 곡선 맵의 **MAP 01: STRAIGHT / TAP**: 직선 맵으로 복귀.
- PC에서는 **M**으로 전환, A/D 조향·S 제동.
- Pleos에서는 기존 SDK 조향·브레이크 사용. 가속페달은 사용하지 않고 자동 가속한다.
- 벽 접촉·실행 제한 후에는 P/정상 입력에서 **RESTART / TAP**으로 정지 출발한다. 맵 전환으로 입력 제한을 우회할 수 없다.

Unreal 맵은 `/Game/Maps/IceRampDrive`, 원본은 `/Game/Maps/IceTrackDrive`다. 상세 실행·APK 빌드 방법은 [Android 실행 안내](ANDROID_RUN.ko.md)에 있다.

## 수정할 원본

- `unreal/BeyondPhysics/Source/BeyondPhysics/Physics/VirtualRamp.h`: 곡률·높이·편경사·노드와 도로 좌표 투영.
- 같은 폴더 `RoadBoundary.h`: 곡선 차체 외곽과 벽·도로 끝 판정.
- 같은 폴더 `VehicleModel.cpp`: 경사에서 중력과 타이어 힘 투영, 정적 수직하중.
- `Driving/DrivingPawn.cpp`: 두 맵 선택, SDK·키보드 조작, 고정 시간 실행, 차량과 카메라의 경사 정렬.
- `UI/DrivingHUD.cpp`: 맵 전환 버튼과 가상 설계 표시.
- `Tests/run-ramp-checks.cmd`: 필요한 계산 확인과 `SourceArt/Ramp/road.csv` 내보내기.
- `Scripts/build_virtual_ramp.py`: CSV로 Unreal 도로 메시와 레벨 생성. 최초 실행은 원본을 저장하지 않고 새 맵 사본에 결과를 저장한다. 명시적인 `RAMP_REFRESH=True`는 이미 생성된 새 맵의 VirtualRamp 폴더를 다시 만든다. 수동 편집 후 재생성 전에는 맵을 별도 백업한다.
- `tools/test_ramp_emulator.ps1`: 시험 전용 가상 운전자. 기본 검사는 실제 APK의 SDK 조향/브레이크로 곡선 진입 후 속도50% 이상 감소를 확인한다. 경사 위 정지 유지 검사는 아니다. `-FullDrive`는 지연에 민감한 미완성 시험 제어기이며 완주 보장을 하지 않는다. APK에 자동 조향을 추가하지 않는다.

형상 수정은 C++ 헤더 수정→노드 CSV 재생성→에디터 메시 재생성→전체 APK 패키징 순서다. 맵·메시 변경에는 `-SkipCook`을 쓰지 않는다. 원본 백업은 `backups/virtual-ramp-20261030`에 있다.

## 물리 모델의 유효 범위

기존 타이어·마찰원·고정 적분을 공유하되, 새 맵은 노면 접평면에 중력과 타이어 힘을 투영하고 준정적 수직하중을 계산한다. 높이 `h(x,y)`의 기울기가 `(hx,hy)`이면 단위 법선은 `n=(-hx,-hy,1)/sqrt(1+hx²+hy²)`, 정적 수직하중은 `N=mg/sqrt(1+hx²+hy²)`다. 중력의 접평면 성분은 `g_t=g_world-(g_world·n)n`이다. 이 힘을 기존 차체 좌표의 속도 방정식에 반영한다.

차체 U,V·요 운동 및 슬립 계산은 작은 경사를 가정한 축소3자유도 근사다. 화면의 피치·롤은 노면에 기하학적으로 정렬한다. 서스펜션, 동적 하중이동, 종단곡률에 따른 동적 수직하중, 이륙·전복, 롤/피치 관성은 계산하지 않는다. 6자유도 실차 재현이나 실측 빙판 타이어 검증으로 설명하지 않는다. 원래 직선 맵의 평면 힘 경로는 유지했다.

자동 가속 요청과 Boolean 브레이크는 기존 맵의 정책을 유지한다. 타이어의 종·횡력은 마찰 한도를 공유하므로 가속·제동 중 조향 여력이 줄어든다. 외부 시험 도구의 1초 간격 전구간 자동 조향은 SDK 지연과 힘 포화에서 불안정해 벽에 닿았다. 이를 완주 성공으로 계산하지 않으며, 게임에 경로 추종·강제 궤도 보정을 넣지 않았다. C++ 전구간 계산 검사의 연속·부분 구동 입력과 실제 APK의 Boolean 제동 입력은 서로 다른 시험 조건이다.

강제동 후에도 횡방향 미끄러짐이 남아 벽 접촉한 사례가 있다. 현재 정규화한 속도 기반 타이어 힘에는 정확한 정지마찰·차륜 잠김/ABS 모델이 없으므로 경사면의 정지 유지 정확성을 보장하지 않는다. 단순히 실제 얼음에서 반드시 발생하는 현상이라고 해석하지 않으며, 실차 교육용 정밀도 개선 항목으로 남긴다.

## 자료 조사에서 확인한 제한

CODIL의 연결로 설계 보고서 CIGCSPB00032는 다운로드 시 로그인 필요 HTML을 반환했다. 공개 연구 보고서 OTKCRK230822에는 설계도 예시와 자료 수집 절차가 있지만, 확보·검토한 내용에서 단일 램프의 전체 선형·종단·편경사·폭원 원본을 함께 복원하지 못했다. OTMCTC090018은 실제 공사 VE 사례집이며 완전한 램프 설계 도면 세트로 사용하지 않았다. 이에 사용자가 가상 램프로 범위를 변경했다. 원본 도로 도면을 확보한 것처럼 보고하지 않는다.
